# learn — أول شريحة: استخراج الذرات من الخارطة

CLI محلية تقرأ فصلًا أو أكثر من خارطة Obsidian، تحل روابط الدروس عبر الـ vault كله، ثم تطلب من
مزود LLM (متوافق مع OpenAI) اقتراح ذرات معرفية بصيغة JSON مقيدة، وتتحقق برمجيًا من كل اقتباس
قبل قبول الرد. الأداة **للقراءة فقط** بالنسبة للـ vault: لا تعدل الدروس ولا الخرائط، وتكتب الناتج
في مسار الإخراج فقط.

## المتطلبات

- Node.js 20+ (تستعمل `fetch` الأصلية).
- `pnpm` (أو `npm` بالأوامر المكافئة).

## التثبيت

```bash
cd app
pnpm install
```

## متغيرات البيئة

| المتغير          | إلزامي                                   | الوصف                                       |
| ---------------- | ---------------------------------------- | ------------------------------------------- |
| `LLM_API_KEY`    | نعم (إلا مع `--resolve-only`)            | مفتاح الـ API                               |
| `LLM_BASE_URL`   | لا (افتراضي `https://api.openai.com/v1`) | عنوان مزود متوافق مع OpenAI                 |
| `LLM_MODEL`      | نعم (إلا مع `--resolve-only`)            | اسم الموديل                                 |
| `LLM_TIMEOUT_MS` | لا (افتراضي `120000`)                    | مهلة طلب المزود بالملي ثانية؛ عدد صحيح موجب |

انسخ `.env.example` إلى `app/.env` واملأ القيم؛ تُقرأ تلقائيًا دون تجاوز متغيرات البيئة الأصلية.
لا يوجد أي مزود أو مفتاح داخل الشفرة، و`.env` و`.learn/` متجاهلان من Git (انظر `.gitignore` بالجذر).
طلب الشبكة يفشل برسالة عربية واضحة عند انتهاء المهلة؛ لا retry تلقائي (لا نكرر طلبًا مدفوعًا).

## الأوامر

### 1) الاستخراج: `learn extract`

من جذر الـ vault (مثال على الخارطة الحالية):

```bash
cd app

# بلا شبكة: تحليل وحل روابط وملخص فقط
pnpm learn extract \
  --roadmap ../roadmaps/L-2-frontend-1-jobran-1.md \
  --chapters 1,2 \
  --resolve-only

# استخراج فعلي عبر المزود
pnpm learn extract \
  --roadmap ../roadmaps/L-2-frontend-1-jobran-1.md \
  --chapters 1,2 \
  --output ../.learn/proposals/frontend-1-ch1-2.json
```

الخيارات:

- `--roadmap <path>`: مسار ملف الخارطة (إلزامي).
- `--chapters <list>`: أرقام الفصول التسلسلية مفصولة بفواصل، مثل `1,2` (إلزامي).
  أعداد صحيحة موجبة كاملة فقط بلا تكرار؛ تُرفض قيم مثل `1abc` و`1.5` و`0` و`2,2` برسائل واضحة.
- `--output <path>`: مسار JSON الناتج (إلزامي إلا مع `--resolve-only`).
- `--resolve-only`: يعرض ملخص الحل (دروس/recap/تمارين/مفقود) ويتوقف قبل أي اتصال بالشبكة.
- `--vault <path>`: جذر الـ vault؛ الافتراضي أقرب مجلد أبٍ للخارطة يحتوي `.obsidian`.
- `--kb <path>`: مسار قاعدة المعرفة لكشف التكرار؛ الافتراضي `.learn/knowledge-base.json`
  تحت جذر الـ vault وتُحمّل تلقائيًا إن وُجدت — فيرى المزود ذراتك المعتمدة
  ويربط ما تكرر منها بحقل `duplicateOf` بدل إنشاء ذرة جديدة.

### 2) المراجعة البشرية: `learn review` (الحفظ التلقائي)

```bash
cd app
pnpm learn review --proposal ../.learn/proposals/frontend-1-ch1-2.json
```

يشغّل خادمًا محليًا (`127.0.0.1` فقط، منفذ حر تلقائيًا) ويفتح صفحة المراجعة في المتصفح.
**كل ضغطة «اعتمد/استبعد» تُكتب فورًا** في ملف القرارات بجانب الاقتراح:
`frontend-1-ch1-2.decisions.json` — لا تنزيل ولا تصدير يدوي، ويمكنك إغلاق الصفحة
والعودة لاحقًا (قراراتك تُقرأ من الملف عند كل تشغيل). مؤشر «محفوظ تلقائيًا» في الهيدر
يتبدل إلى خطأ إن تعذر الحفظ (ويبقى قرارك محفوظًا محليًا في المتصفح كنسخة احتياطية).

- الخيارات: `--proposal <path>` (إلزامي)، `--port <number>` (اختياري).
- الكتابة ذرّية (ملف مؤقت ثم rename) فلا يتلف الملف عند انقطاع مفاجئ.
- زر «تصدير القرارات» ما زال موجودًا في صفحة `file://` القديمة للطوارئ فقط.

### 3) الاعتماد الدائم: `learn commit`

```bash
cd app
# الافتراضي: يقرأ frontend-1-ch1-2.decisions.json بجانب الاقتراح تلقائيًا
pnpm learn commit --proposal ../.learn/proposals/frontend-1-ch1-2.json

# أو تمرير ملف قرارات صادر عن زر التصدير يدويًا
pnpm learn commit \
  --proposal ../.learn/proposals/frontend-1-ch1-2.json \
  --decisions ~/Downloads/review-decisions.json
```

- المعتمد يُحفظ في `.learn/knowledge-base.json` بمعرفات ثابتة (`k0001`…).
- ذرة `duplicateOf` لا تُنشئ جديدة؛ تدمج مصادرها (بلوكات الدروس) في الذرة القائمة.
- المرفوض/بلا قرار يُتجاهل، وإعادة تنفيذ الأمر نفسه لا يكرر (idempotent).
- أي `extract` لاحق يحمّل القاعدة تلقائيًا فلا يقترح تكرارًا لذراتك المعتمدة.

أكواد الخروج: `0` نجاح، `1` خطأ عام (ملف مفقود، متغيرات ناقصة، صيغة فصول...)، `2` فشل تحقق
(غموض أسماء، رد LLM مرفوض).

### ملف الرفض التشخيصي `.rejected.json`

عندما يصل رد من المزود ثم يفشل أي من مراحل التحقق — `json` أو `schema` أو `semantic` — تُنشئ
الأداة ملفًا بجانب `--output` باسم `<name>.rejected.json` (يُستبدل امتداد `.json` بالناتج)
كي لا يضيع الرد المرفوض قبل مراجعته. محتواه:

- `schemaVersion` تشخيصي (1) و`kind: "rejected-llm-response"` والوقت (`generatedAt`) والموديل.
- `stage`: مرحلة الفشل (`json` | `schema` | `semantic`).
- `error` و`issues`: الأخطاء كاملة بلا اختصار.
- `rawResponse`: الرد كما أعاده المزود حرفيًا، و`parsedResponse` بعد JSON.parse إن نجح (يغيب عند فشل الـ JSON).

قيود الخصوصية والسلوك:

- لا يتضمن أي prompts أو محتوى دروس أو متغيرات بيئة أو base URL أو مفاتيح — فقط ما أنتجه المزود وما استنتجه التحقق منه.
- يُكتب فقط لأخطاء رد المزود بعد استلامه؛ أخطاء التحضير/الشبكة/الإعداد لا تنشئه.
- كتابته ليست نجاحًا: لا يُكتب ملف الناتج المقبول، وكود الخروج يبقى `2`.
- إن تعذرت كتابته، يُعرض خطأ الحفظ إضافةً إلى خطأ التحقق الأصلي دون أن يطمسه.

## سلوك التحليل

1. يفهم القائمة المرقمة بمستوييها: مستوى أول فصول، ومستوى ثانٍ عناصر.
2. يصنف كل عنصر إلى:
   - `lesson`: رابط wiki يُحل إلى ملف موجود، وليس ملف recap.
   - `exercise`: يحمل `❌` (رابطًا كان أم نصًا) — يُستبعد من الاستخراج.
   - `recap`: ملف عنوانه `Chapter recap` أو `Chapter N recap` — مادة تحقق وتغطية فقط، لا مصدر ذرات.
   - `missing`: بلا رابط أو رابطه بلا ملف — يُبلَّغ عنه ولا يُخترع محتواه.
3. يحل الروابط بالبحث في كامل الـ vault:
   - `[[Name]]` بالاسم (basename)، مثل `lessons/Intro to HTML.md` أو ملفات الجذر.
   - `[[path/Name]]` و`[[path/Name.md|alias]]` بالمسار النسبي لجذر الـ vault
     (توحيد `/` وتحمّل `.md`)، ويُرفض الخروج من الـ vault عبر `..`.
   - عند تعدد الملفات بنفس الاسم (في الروابط بالاسم) يفشل برسالة ambiguity تسمي كل المرشحين.
4. **تحضير واحد**: تُحلَّل الخارطة وتُفهرس وتُحل العناصر مرة واحدة في خطة موحدة
   (`preparePlan`) يستهلكها الملخص والاستخراج معًا، فلا انحراف بين المعروض والمُرسل؛
   ومجلد الأداة نفسه (`app/`) مستبعد من الفهرسة.
5. لا يتصل بالشبكة إلا في وضع الاستخراج الفعلي، وبعد طباعة ملخص ما سيُرسل.

## عقد الناتج (v2)

قبل الإرسال تُقسَّم الدروس الأساسية إلى **بلوكات مصدر ثابتة** (`src/domain/blocks.ts`): أصغر وحدة
تعليمية طبيعية — فقرة، بند قائمة (بمحتواه دون بنوده الأبناء)، أو كتلة شفرة — بمعرف deterministic
مثل `lessons/One.md#b001` ونطاق أسطر وقسم أقرب عنوان. البلوكات تُرسل للمزود بدل المستند المبهم،
والعناوين ليست بلوكات، والصور المنفردة تُمثل بنصها البديل (alt).

ملف JSON (`schemaVersion: 2`) يحوي: مسار الخارطة والفصول، الدروس الأساسية، البلوكات كما أُرسلت
(`blocks`)، ملفات recap للتحقق، التمارين المستبعدة، العناصر المفقودة، الذرات المقترحة (كل ذرة:
`clientId` و`title` و`statement` و`kind` من سبعة أنواع — منها `fact` و`constraint` — و`sourceRefs`
تشير إلى بلوك عبر `blockId` مع اقتباس `evidence` حرفي، و`prerequisites` و`related` و`confidence`)،
مصفوفة `coverage` لكل بلوك أساسي (إما `covered` بذرات أو `excluded` بسبب مسموح:
`administrative | course_meta | media_only` مع `note`)، وتحذيرات التغطية والتكرار.
التعريف الكامل في `src/schema/proposal.ts`.

التحقق بعد رد المزود (رفض لا إصلاح صامت):

- **Grounding داخل البلوك**: `sourceRefs` يجب أن تشير إلى بلوك معروف يخص الملف المذكور،
  والاقتباس موجود حرفيًا **داخل ذلك البلوك** لا في مكان آخر من الملف. تُجرّب أولًا مطابقة
  النص الخام بعد تطبيع المسافات، فإن فشلت تُجرّب بعد تحويل الطرفين إلى النص المرئي لـ Markdown
  (إزالة محارف emphasis/strong/inline-code، تحويل الروابط إلى نصها، توحيد NBSP) عبر `markdown-it`.
  فروق العرض فقط تمر؛ حذف كلمة أو إعادة ترتيب أو صياغة أو `...` تبقى مرفوضة.
- **Coverage كامل**: كل بلوك أساسي مرة واحدة بالضبط في `coverage`؛ بلا تكرار، وبلا بلوك
  مسقوط، و`covered.atomIds` غير فارغة وتشير لذرات معروفة، وكل ذرة مشمولة ببلوك covered واحد
  على الأقل. الاستشهاد بملف recap (المرئي للتحقق فقط) مرفوض.
- أخطاء coverage تُعتبر semantic errors وتظهر كاملة في ملف `.rejected.json` كما بقية الأخطاء.
- علاقة بـ `clientId` مجهول، أو تكرار `clientId`، أو ثقة خارج `[0,1]`، أو رد بلا ذرات.

## التطوير

```bash
pnpm typecheck   # tsc --noEmit
pnpm test        # vitest run (بلا شبكة إطلاقًا؛ المزود وfetch مبطنان)
pnpm format      # prettier --write .
pnpm format:check
```

البنية:

- `src/domain/`: تحليل الخارطة وقائمة الفصول وفهرسة الـ vault وحل الروابط والتحضير الموحد (`plan.ts`)،
  وتقسيم الدروس إلى بلوكات مصدر ثابتة (`blocks.ts`).
- `src/llm/`: عميل OpenAI-compatible بمهلة، بناء الرسائل، تنسيق التدفق والتحقق، وملف التشخيص `.rejected.json` (`artifact.ts`).
- `src/schema/`: عقد Zod والتحقق الدلالي.
- `prompts/extract-system.md`: قواعد الـ prompt المستقلة القابلة للتعديل والاختبار.
- `src/review/`: صفحة المراجعة المكتفية بذاتها (`page.ts`) وخادم المراجعة المحلي
  بحفظ القرارات اللحظي (`server.ts`).
- `src/cli.ts`: واجهة commander — طبقة رقيقة فوق منطق المجال ليُستعمل لاحقًا من API.

## التوسع لاحقًا

الحزمة مفردة تحت `app/`. للتحول إلى workspace: أضف `pnpm-workspace.yaml` بالجذر
(مثل `packages: ["app", "packages/*"]`) دون أي تغيير في الشفرة؛ منطق المجال والـ LLM منفصلان
عن CLI ليمكن استدعاؤهما من خدمة API مباشرة.
